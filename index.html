The four checks

01 — Shopify → Meta CAPI / GA4

Idempotent purchase events

The duplicate is the failure mode. An order is delivered three times by the webhook; the bridge derives event_id = sha256(order_id + currency + total) and keeps a 30-day window of ids it has already sent.

  • 3 deliveries → 4 outbound events (Meta CAPI + GA4), the retry emits 0.
  • Runs end to end against a local n8n workflow and a mock receiver — test_dedup.py, 5 assertions.
  • The suite starts its own mock receiver on :8799 and kills it on exit — a leftover receiver from an earlier session is what makes this kind of test lie.
  • Files: shopify-tracking/
02 — Deliverability

SPF / DKIM / DMARC gate with an exit code

0 = send is safe, 1 = critical defect. A scheduler can open a ticket on the exit code alone.

  • Honours the RFC 7208 ten-lookup ceiling instead of pretending it does not exist.
  • Measured on real domains: github.com 10/10 lookups, shopify.com p=reject → WARN, example.com revoked DKIM → FAIL, exit 1.
  • Files: deliverability/
03 — DMARC reporting

What the aggregate reports actually say

Parses rua reports, raw or gzipped, namespace-tolerant. It does not stop at “DMARC is configured”: it reports which IPs sent as your domain, how many messages failed alignment, and what the policy did about it.

  • Fixture: 98 spoofed messages from a single IP, disposition none — the record exists and blocks nothing.
  • Files: deliverability/dmarc_report.py
04 — Klaviyo

Flow audit with a third verdict

Audits five flows: abandoned checkout, browse abandonment, welcome, post-purchase, win-back. Two lessons came from running it, not from a checklist:

  • Klaviyo names the flow “Abandoned Cart”. A naive matcher on “abandoned checkout” reports it missing when it is live.
  • When the export carries no step detail the flow is UNSCORED, never OK — and a critical UNSCORED fails the store.
  • Files: klaviyo-audit/

What this is not

No proof here ran against a live client store. The DMARC fixtures are synthetic (documentation IP ranges), the Klaviyo exports are shaped like the real API but hand-built, and the Shopify workflow was exercised against a mock receiver, not against Shopify's production endpoint. What is real: the logic, the failure cases, the exit codes, and the outputs above. Where a client deployment needs a token, an approved app or a mailbox that receives rua= mail, this says so in the README of each folder instead of hiding it.
